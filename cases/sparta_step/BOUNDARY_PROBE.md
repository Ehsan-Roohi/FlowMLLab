# CPU boundary-window diagnostic (experimental)

Three completed step cases show excessive temporal drift: h/H=0.16 with seeds
20260905/20260917, and h/H=0.21 with seed 20260917. Net open-boundary mass flux
remains forward in their recorded blocks. Large speed excursions coincide with
inlet injection and inventory excursions. A cause has not been established.

The pinned SPARTA source already applies an exponential velocity average in
`emit/surf`, but not `emit/face`. `patch_face_window.py` ports that arithmetic to
the CPU pressure-and-temperature branch of `emit/face` as optional
`subsonic P T window N`. The patch checks exact source hashes before writing.
Window=0 preserves the original arithmetic. Positive windows are rejected for
Kokkos and pressure-only operation. Density, temperature, weights, collisions,
geometry and mesh are unchanged. This is a diagnostic candidate, not a verified
physical correction.

The average is reset when emit tasks are rebuilt, including run initialization,
grid changes and restart. There is no dynamic balancing in these probes. The
new sampling segment runs without a final one-block split. Its first 10000-step
field block is much longer than either averaging window. Continued attempts
use a full new settling and sampling window; old running averages are not
stitched or claimed to be restored.

Nine arms compare N=0,50,200 for each of the three cases, beginning from the same
verified warm checkpoint within each case and using the same seed. Each arm
settles for 40000 steps then samples for 120000 steps at the original timestep.
The grid is 1000x200 and the original particle weight is preserved. Net flux and
inventory are logged every 100 steps; spatial blocks remain 10000 steps.
The initial particle estimate remains at or below 5.1 million. This is not a
hard cap on the naturally changing particle population in an open domain.

Submit uses 16 CPUs / 16 GiB per arm, at most three concurrent arms, and reserves
all other account jobs (including pending cylinder chains) against the previously
verified 1000-CPU account quota with at least three spare CPUs. The build and
MPI preflight must pass before the array starts. Original source and production
jobs are not modified. `LATEST_SPARTA_STEP_BOUNDARY_PROBE` prevents duplicate
campaign submission; queued/running tasks must not be resubmitted manually.

Preflight includes positive windows, changed-rank restart (2 to 4 MPI ranks),
and an exact field comparison between window=0 and the original executable,
with identical run segmentation and diagnostics. Serial preflight passed.
Actual MPI preflight is run on Unity after build.

The review writes `boundary_comparison.json` and does not approve data
automatically. Acceptance requires pressure fidelity, temporal stationarity,
and agreement between the two nonzero windows; suppressing visible noise is
insufficient. Local reversal/reattachment and mesh independence need separate
evidence. No plots are generated by this diagnostic.
